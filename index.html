Why tables usually come out wrong

Most exporters read the page once and take whatever is on screen. That works on a simple table and fails on everything else.

You get 14 rows out of 4,000

Modern tables only keep the visible rows in the page. Everything else exists nowhere until you scroll. Most extractors never tell you.

Merged cells shift every row below

A single rowspan pushes the rest of the column out of alignment. The file looks fine until someone checks a number against the source.

Excel turns 007 into 7

And a 19-digit order number into 1.23457E+19. Zip codes, SKUs and phone numbers all lose their meaning the moment they're treated as arithmetic.

Grids aren't tables

React grids, ag-Grid and web components draw rows out of ordinary divs. A naive extractor looking for <table> sees an empty page.

What TableJack does about it

It tells you when the page is hiding rows

When a table reports more rows than it is actually rendering, TableJack says so before you export — not after you've already pasted an incomplete sheet into a report.

Then it goes and gets the rest

Grab all rows scrolls the table to the end, collects every row as it appears, de-duplicates, and puts your scroll position back exactly where it was. 4,382 rows out of a table that only ever had 14 in the page.

Paginated tables become one sheet

Follow pages clicks the site's own next-page control, waits for each page to settle, merges everything and removes duplicates. It also clicks "load more" on infinite-scroll lists until they run out.

Merged cells expanded properly

Every rowspan and colspan is filled out into a proper rectangular grid, so column N means the same thing on every row.

IDs stay IDs

Leading zeros, leading plus signs, anything over 15 digits and anything that looks like exponent notation are written as text. 007 stays 007.

Finds tables anywhere

Real <table> tags, ARIA grids, shadow DOM web components and same-origin iframes. Each one named from its caption or nearest heading.

Spreadsheets that open clean

Bold frozen header row, autofilter on, sensible column widths, UTF-8 handled correctly so café stays café. CSV gets a BOM so Excel on Windows behaves.

Questions

Is $5.99 really one payment?

Yes. It is a one-time purchase, not a subscription. Nothing renews and you will not be charged again. The licence terms say so in writing.

Do I have to enter a licence key?

No. After you pay you land on a thank-you page that switches Pro on by itself. If that ever fails — an ad blocker, a closed tab, a different browser — the key is on the page and in your receipt email, and the extension's options page has a box to paste it into.

How many computers can I use it on?

Three. That covers a desktop, a laptop and a spare. If you replace a machine you can remove the licence from the old one in the extension's options page, which frees the slot.

What if it doesn't work on the table I need?

Install it free first and try it on that exact table. Free has every bit of the correctness work in it — merged cells, number handling, grid detection — so if the first 50 rows come out right, the rest will too. That is the whole point of the free tier having a row cap rather than a feature cap.

If it still doesn't work, there is a 7-day refund and you don't have to explain why.

What can't it do?

Tables drawn on a canvas — Google Sheets and some dashboards — are pixels, not data, and cannot be read by anything short of OCR. PDFs are out of scope. And cross-origin frames that Chrome blocks from scripting stay blocked; that is Chrome's decision, not ours.

Which browsers?

Chrome 116 and later, and Chromium browsers that install from the Chrome Web Store — Edge, Brave, Arc, Opera, Vivaldi. Not Firefox or Safari.

What happens if you stop selling it?

Your copy keeps working. If the activation service ever goes away the extension is built to fail open — an unreachable server never downgrades a licence that already activated. The terms cover this explicitly.
